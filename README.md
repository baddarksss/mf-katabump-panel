# M&F Katabump 2.4.1

### اسم ساب برای هر کلاینت

- عنوان ساب در خروجی‌های `/sub/`، `/json/` و `/clash/` به‌صورت پیش‌فرض نام کلاینت است؛ مثلاً کلاینت `alo` با همین عنوان به برنامه معرفی می‌شود.
- در بخش **Clients → Edit → اسم ساب** عنوان دلخواه وارد کنید و همان فرم را ذخیره کنید. خالی‌کردن این فیلد عنوان را به نام کلاینت برمی‌گرداند.
- نام سفارشی در `vpn/data/mf_gateway.json` ذخیره می‌شود و بعد از ری‌استارت و آپدیت باقی می‌ماند. لینک ساب عوض نمی‌شود.
- برنامه‌هایی که عنوان اشتراک موجود را ثابت نگه می‌دارند ممکن است برای نمایش نام جدید به واردکردن دوبارهٔ لینک نیاز داشته باشند.

نسخهٔ راه‌انداز M&F روی Katabump. این ریپو در ریشه فقط چهار فایل دارد و نصب هم فقط دو فایل اجرایی می‌خواهد:

```text
index.js               راه‌انداز کامل (ساب، نود، آمار، Xray، آپدیت، برند)
package.json           نسخه و اسکریپت‌ها
README.md              همین راهنما
update-manifest.json   فقط برای آپدیتر GitHub
```

پوشهٔ `main/` نسخهٔ اصلی و دست‌نخوردهٔ سورس قبلی است؛ برای نصب لازم نیست.

## نصب / آپدیت

1. فقط `index.js` و `package.json` را در مسیر اصلی پروژهٔ Katabump جایگزین کنید.
2. پوشهٔ `vpn/` را نگه دارید. دیتابیس، کلاینت‌ها، UUID، `Sub ID`، سهمیه‌ها، لینک‌های فعلی و تنظیم نسخهٔ Xray داخل آن است.
3. یک بار Restart بزنید. فرمان اجرا `node index.js` است.
4. صفحه را با `Ctrl+F5` باز کنید و اگر لازم شد دوباره وارد شوید.

پورت عمومی از `SERVER_PORT` (یا `PORT`) خوانده می‌شود. سه پورت داخلی پیش‌فرض `18080` (پنل)، `18081` (گیت‌وی) و `18082` (ساب) هستند و در صورت تداخل با `PANEL_PORT` / `USER_PORT` / `SUB_PORT` عوض می‌شوند.

## چه چیزی در 2.4.0 عوض شد

- **کارت SYSTEM STATUS:** اعداد CPU، RAM، Swap، Storage و Uptime از خود کانتینر خوانده می‌شوند، نه از میزبانی که با بقیه مشترک است. RAM به‌صورت working set (بدون page cache) حساب می‌شود، نبود swap به‌صورت `0 B / 0 B` نشان داده می‌شود و هیچ‌وقت `NaN%` یا `Infinity%` نمی‌آید. Load average، مدل CPU و شبکه همان مقادیر میزبان می‌مانند.
- **نسخه در پنل:** کاشی VPN-UI نسخهٔ M&F (مثلاً `v2.4.0`) را نشان می‌دهد و نسخهٔ هستهٔ `vpn-ui` در tooltip همان کاشی است.
- **آپدیتر Xray:** داخل کادر M&F بخش «هستهٔ Xray» فهرست نسخه‌های رسمی را از GitHub می‌گیرد، باینری XTLS را دانلود و با SHA256 تأیید می‌کند، بعد Xray را متوقف، فایل را جایگزین و دوباره روشن می‌کند. اگر نسخهٔ جدید بالا نیاید، نسخهٔ قبلی برمی‌گردد. هستهٔ `vpn-ui` هر بار در استارت، Xray خودش را برمی‌گرداند؛ راه‌انداز انتخاب شما را در `vpn/data/xray-target.json` نگه می‌دارد و بعد از هر ری‌استارت (و هر ۶۰ ثانیه یک بار) دوباره اعمال می‌کند.
- **آپدیت از داخل پنل:** دکمهٔ `Check for update — GitHub` در کادر M&F نسخهٔ جدید را می‌گیرد، سپس پنل ری‌استارت می‌شود و نسخهٔ نمایش‌داده‌شده عوض می‌شود؛ کلاینت‌ها و لینک‌ها دست نمی‌خورند.
- **ساب کلاینت:** ساب به‌صورت خودکار و با آدرس واقعی مرورگر تنظیم می‌شود. در ردیف هر کلاینت لینک `Sub` ظاهر می‌شود و لینک‌ها روی همان دامنه و پورت عمومی ساخته می‌شوند.
- **خطای 404:** مسیرهای بدون پیشوند `/kb/` با `307` به مسیر درست منتقل می‌شوند و پاسخ‌های HTML کش نمی‌شوند. فهرست آخرین درخواست‌های 404 هم داخل کادر M&F دیده می‌شود.
- **بهینه‌سازی برای پلن کوچک:** زیر ۱.۵ گیگابایت cgroup، `GOGC=60` در کنار `GOMEMLIMIT` تنظیم می‌شود؛ لاگ‌های بزرگ‌تر از ۸ مگابایت در استارت خالی می‌شوند و فایل‌های نیمه‌کارهٔ `.part`، staging و `.xray-*` پاک می‌شوند.
- نسخهٔ راه‌انداز از `package.json` خوانده می‌شود و دیگر عدد ثابت در کد نیست.

نسخهٔ هستهٔ `vpn-ui` را این نسخه تعویض نمی‌کند. اگر هستهٔ نصب‌شده `1.9.2` باشد، همان می‌ماند و فقط برچسب پنل عوض می‌شود؛ برای ارتقای هسته، نسخهٔ 1.9.4 به‌صورت جداگانه دانلود و جایگزین می‌شود (دیتابیس `vpn/` حفظ می‌شود). به‌روزرسانی Xray از این نسخه مستقل انجام می‌شود.

## ریپوی خصوصی و آپدیت

در GitHub از Settings > Developer settings > Personal access tokens > Fine-grained tokens توکن بسازید. Only select repositories را برای همین ریپو انتخاب و Repository permissions > Contents را Read-only کنید.

در Environment / Startup سرویس Katabump این دو متغیر را تنظیم کنید:

```text
GITHUB_REPOSITORY=owner/repository
GITHUB_TOKEN=توکن_جدید
```

برنامه فایل `.env` نمی‌خواند؛ این‌ها باید متغیر محیطی واقعی پروسه باشند. توکن در سورس، manifest، staging، لاگ یا بستهٔ نصب ذخیره نمی‌شود. بدون `GITHUB_REPOSITORY` مقدار `updateRepository` در `package.json` استفاده می‌شود.

در پنل، از کادر M&F دکمهٔ **Check for update — GitHub** را بزنید. خطای 401 یعنی توکن نامعتبر/منقضی؛ 404 یعنی نام ریپو، دسترسی خصوصی، شاخهٔ `main` یا manifest پیدا نشد. آپدیتر فقط `index.js` و `package.json` را جایگزین می‌کند (با SHA256، syntax-check و بکاپ) و کلاینت‌ها دست نمی‌خورند.

## انتشار نسخهٔ بعدی

```bash
npm test
npm run release
```

`index.js`، `package.json` و `update-manifest.json` را در یک commit روی `main` بگذارید. manifest برای GitHub لازم است و روی Katabump بارگذاری نمی‌شود.

## آمار کانتینر

CPU و RAM از cgroup خود کانتینر خوانده می‌شوند (RAM = `memory.current` منهای `inactive_file`). مصرف دیسک از پوشهٔ سرور هر ۶۰ ثانیه اندازه‌گیری می‌شود؛ برای سقف ۵ گیگابایت `KATABUMP_DISK_MB=5120` را تنظیم کنید (یا `SERVER_DISK` / `DISK`). اگر سقفی تنظیم نشده باشد، همان سقف پنل نشان داده می‌شود و یک یادداشت کوتاه زیر کارت می‌آید. Uptime مدت اجرای راه‌انداز است و شبکه از namespace کانتینر بدون loopback خوانده می‌شود.

## آزمون‌ها

مسیریابی، تزریق برند، `Connection: close`، ریدایرکت `307`، فعال‌سازی خودکار ساب، تولید لینک `/sub/<id>`، حفظ داده‌ها، کارت SYSTEM STATUS با مقادیر کانتینر، نصب و برگشت‌پذیری Xray، اعمال دوبارهٔ Xray بعد از ری‌استارت پنل و اجرای مستقل دو‌فایلی روی Linux amd64 با هستهٔ `vpn-ui 1.9.4` آزمایش شده‌اند.
