# M&F Katabump 2.3.2

نسخهٔ راه‌انداز M&F روی Katabump. این ریپو در ریشه فقط چهار فایل دارد و نصب هم فقط دو فایل اجرایی می‌خواهد:

```text
index.js               راه‌انداز کامل (ساب، نود، آمار، آپدیت، برند)
package.json           نسخه و اسکریپت‌ها
README.md              همین راهنما
update-manifest.json   فقط برای آپدیتر GitHub
```

پوشهٔ `main/` نسخهٔ اصلی و دست‌نخوردهٔ سورس قبلی است؛ برای نصب لازم نیست.

## نصب / آپدیت

1. فقط `index.js` و `package.json` را در مسیر اصلی پروژهٔ Katabump جایگزین کنید.
2. پوشهٔ `vpn/` را نگه دارید. دیتابیس، کلاینت‌ها، UUID، `Sub ID`، سهمیه‌ها و لینک‌های فعلی داخل آن است.
3. یک بار Restart بزنید. فرمان اجرا `node index.js` است.
4. صفحه را با `Ctrl+F5` باز کنید و اگر لازم شد دوباره وارد شوید.

## چه چیزی در 2.3.2 عوض شد

- **نمایش نسخه:** کاشی VPN-UI دیگر نسخهٔ هسته را به‌جای نام پنل نشان نمی‌دهد. نسخهٔ M&F (مثلاً `v2.3.2`) نمایش داده می‌شود و نسخهٔ هستهٔ `vpn-ui` در tooltip همان کاشی می‌ماند.
- **ساب کلاینت:** ساب به‌صورت خودکار و با آدرس واقعی مرورگر تنظیم می‌شود. بعد از اولین باز شدن پنل، در ردیف هر کلاینت دکمه/لینک `Sub` ظاهر می‌شود و لینک‌ها روی همان دامنه و پورت عمومی ساخته می‌شوند.
- **خطای 404:** مسیرهای قدیمی پنل که بدون پیشوند `/kb/` درخواست شوند (مثل `/panel/...` یا `/assets/...`) با `307` به مسیر درست منتقل می‌شوند تا تب‌ها و درخواست‌های POST هم کار کنند. پاسخ‌های HTML دیگر کش نمی‌شوند تا صفحهٔ قدیمی با base path قدیمی در مرورگر نماند.
- **تشخیص 404:** داخل کادر M&F فهرست آخرین درخواست‌های 404 (هم از مرورگر و هم از سرور) نمایش داده می‌شود؛ اگر خطایی ماند، همان مسیر دقیقاً مشخص است.
- نسخهٔ راه‌انداز از `package.json` خوانده می‌شود و دیگر عدد ثابت در کد نیست.

نسخهٔ هستهٔ `vpn-ui` را این نسخه تعویض نمی‌کند. اگر هستهٔ نصب‌شده `1.9.2` باشد، همان می‌ماند و فقط برچسب پنل عوض می‌شود؛ برای ارتقای هسته، نسخهٔ 1.9.4 به‌صورت جداگانه دانلود و جایگزین می‌شود (دیتابیس `vpn/` حفظ می‌شود). هستهٔ فعلی آپدیت مستقل Xray را قفل کرده است.

## ریپوی خصوصی و آپدیت

در GitHub از Settings > Developer settings > Personal access tokens > Fine-grained tokens توکن بسازید. Only select repositories را برای همین ریپو انتخاب و Repository permissions > Contents را Read-only کنید.

در Environment / Startup سرویس Katabump این دو متغیر را تنظیم کنید:

```text
GITHUB_REPOSITORY=owner/repository
GITHUB_TOKEN=توکن_جدید
```

برنامه فایل `.env` نمی‌خواند؛ این‌ها باید متغیر محیطی واقعی پروسه باشند. توکن در سورس، manifest، staging، لاگ یا بستهٔ نصب ذخیره نمی‌شود. بدون `GITHUB_REPOSITORY` مقدار `updateRepository` در `package.json` استفاده می‌شود.

در پنل، از کادر M&F دکمهٔ **Check for update — GitHub** را بزنید. خطای 401 یعنی توکن نامعتبر/منقضی؛ 404 یعنی نام ریپو، دسترسی خصوصی، شاخهٔ `main` یا manifest پیدا نشد. آپدیتر فقط `index.js` و `package.json` را جایگزین می‌کند (با SHA256، syntax-check و بکاپ) و کلاینت‌ها دست نمی‌خورند.

## انتشار نسخهٔ بعدی

```bash
npm test
npm run release
```

`index.js`، `package.json` و `update-manifest.json` را در یک commit روی `main` بگذارید. manifest برای GitHub لازم است و روی Katabump بارگذاری نمی‌شود.

## آمار کانتینر

CPU و RAM از cgroup خوانده می‌شوند (RAM شامل cache است). مصرف دیسک از پوشهٔ سرور هر ۶۰ ثانیه اندازه‌گیری می‌شود؛ برای سقف ۵ گیگابایت `KATABUMP_DISK_MB=5120` را تنظیم کنید. نبودن سقف یعنی «نامعلوم»، نه ظرفیت میزبان. Uptime مدت اجرای راه‌انداز است و شبکه از namespace کانتینر بدون loopback خوانده می‌شود.

## آزمون‌ها

مسیریابی، تزریق برند، `Connection: close`، ریدایرکت `307` مسیرهای بدون `/kb/`، فعال‌سازی خودکار ساب، تولید لینک `/sub/<id>`، حفظ داده‌ها و اجرای مستقل دو‌فایلی روی Linux amd64 با هستهٔ `vpn-ui 1.9.2` و `1.9.4` آزمایش شده‌اند. اتصال واقعی به حساب Katabump کاربر باید در نهایت روی همان میزبان تأیید شود.
