# M&F Katabump 2.3.1

این ریپو فقط چهار فایل دارد: index.js، package.json، README.md و update-manifest.json.

برای نصب فقط index.js و package.json را در مسیر اصلی Katabump جایگزین کنید. پوشه vpn را نگه دارید؛ دیتابیس، کلاینت‌ها و شناسه ساب در این پوشه باقی می‌مانند. فرمان اجرا node index.js است. یک بار Restart و سپس صفحه را با Ctrl+F5 باز کنید و در صورت نیاز دوباره وارد شوید. مسیر ورود /kb/ است.

نسخه راه‌انداز M&F برابر 2.3.1 و نسخه هسته vpn-ui برابر 1.9.4 است. نمایش 1.9.4 به معنی نصب‌نشدن راه‌انداز جدید نیست. این نسخه هسته را تعویض نمی‌کند. هسته فعلی آپدیت مستقل Xray را قفل کرده است.

## اصلاحات 2.3.1

- بستن اتصال HTTP سرویس gateway برای جلوگیری از استفاده مجدد مرورگر از اتصال با مقصد اشتباه در مسیریاب تک‌پورت.
- انتقال درخواست‌های مدیریتی به /kb/mf/ تا کوکی ورود با Path=/kb/ ارسال شود.
- کد مدیریت، ساب، نود، آمار و آپدیت داخل index.js است؛ ماژول جانبی لازم نیست.

## ریپوی خصوصی

در GitHub از Settings > Developer settings > Personal access tokens > Fine-grained tokens توکن بسازید. Only select repositories را برای همین ریپو انتخاب و Repository permissions > Contents را Read-only کنید.

در Environment / Startup سرویس Katabump تنظیم کنید:

```text
GITHUB_REPOSITORY=owner/repository
GITHUB_TOKEN=توکن_جدید
```

سپس Restart کنید. توکن را در سورس یا GitHub ذخیره نکنید. برنامه فایل .env را نمی‌خواند؛ این‌ها باید متغیر محیطی واقعی پروسه باشند. اگر میزبان اجازه تنظیم نمی‌دهد، از پشتیبانی میزبان بخواهید متغیرها را اضافه کند. بدون GITHUB_REPOSITORY مقدار updateRepository در package.json استفاده می‌شود.

در پنل Check for update — GitHub را بزنید. توکن در درخواست به api.github.com استفاده می‌شود. خطای 401 یعنی توکن نامعتبر/منقضی؛ 404 می‌تواند ناشی از نام ریپو، دسترسی خصوصی، شاخه main یا manifest مفقود باشد. برای نصب اولیه از نسخه‌های چندفایلی، دو فایل جدید را دستی بارگذاری کنید.

## انتشار نسخه بعدی

بعد از تغییر index.js و افزایش version در package.json:

```bash
npm test
npm run release
```

index.js، package.json و update-manifest.json را در یک commit روی main منتشر کنید. manifest برای GitHub لازم است و روی Katabump نیاز به بارگذاری ندارد. آپدیتر فقط دو فایل اجرایی را جایگزین و از فایل‌های قبلی بکاپ تهیه می‌کند. بعد از اعمال، پروسه خارج می‌شود؛ اگر میزبان خودکار آن را راه‌اندازی نکرد، Restart بزنید.

## آمار کانتینر

CPU و RAM از cgroup خوانده می‌شوند؛ RAM شامل cache است. مصرف دیسک از پوشه سرور هر 60 ثانیه اندازه‌گیری می‌شود. برای سقف 5 GiB متغیر KATABUMP_DISK_MB=5120 را تنظیم کنید. نبودن سقف به معنی نامعلوم است، نه ظرفیت دیسک میزبان. شبکه از namespace کانتینر بدون loopback خوانده می‌شود؛ در شبکه اشتراکی ممکن است مختص یک پروسه نباشد. Uptime مدت اجرای راه‌انداز است. داده ناموجود در بخش ابزارها اعلام می‌شود.

آزمون‌های محلی مسیریابی، کوکی مسیر مدیریت، Connection: close، checksum، حفظ داده‌ها و اجرای مستقل پاس شده‌اند. اتصال واقعی به Katabump کاربر هنوز آزمایش نشده است. نود adapter عملیات پایه است و قرارداد کامل 3x-ui جدید و سهمیه تجمیعی چندنود را پشتیبانی نمی‌کند.
